The earlier timeline, feedback ownership, Random, and protocol approvals were not reopened. No tests were rerun during this review.

**Reproducer for #5.** On the receiving peer, `_animate` stores the previous noisy shot target in `_aim` (display clamps x to −.06..1.06 and y to −.05..1.03). On the next local turn, a recognized pan can end before its first update. The default Flutter drag-start behavior does not guarantee an update on acceptance. `_beginDrag` preserves the inherited aim, power and curve, and `_endDrag` passes them straight into `_takeShot`. For example, a genuine shot with requested x=.985, curve=1, power=1 and x-noise=.030 sends 1.033. The next short release with x-noise=.010 sends 1.061, above the receiver's 1.0415 ceiling. Both noise values are inside the existing ±.0385 producer bound. This can leave one peer waiting indefinitely. Including the display clamp yields the safe wire envelopes x=−.1165..1.1165 and y=−.0885..1.0685, without changing outcome math or Random calls.

**Specification verdict: changes required.** Close #4 by accepting a fresh eligible keeper drag and discarding an interrupted one. Close #5 by accepting the full reachable producer envelope while still rejecting malformed/out-of-range packets before the pending slot.

**Code-quality verdict: changes required.** The never-armed gesture flag and the duplicated assumption about target ranges both have observable consequences. Add focused behavior checks for a newly armed elite keeper after pause, and for a no-update release using an inherited edge aim. The existing declared-boundary tests alone cannot detect divergence from the actual sender. No additional blockers were found in the other three scoped items.
